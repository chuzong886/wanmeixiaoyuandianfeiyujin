# 天枢 · 完美校园电量预警

面向宿舍用电场景的自部署监控系统：查询剩余电量，记录用电变化，通过多尺度模型估算剩余时间，并按风险调整自动查询频率。

**纯 PHP 后端 + MySQL/MariaDB + 宝塔定时任务**，无需 Python 服务、Composer 或常驻队列。Python 仅用于开发时的敏感信息检查和源码打包。

> 本仓库为 3.0.1 脱敏源码，包含后续嵌入式验证码及资源加载修复。没有预置学校/学院编码、学号、宿舍标识、手机号、通知 Token 或 ESA 身份配置。查询信息需要使用者自行提供，仅用于自己有权访问的账户。

最新变更见 [3.0.1更新说明](3.0.1更新说明.md)：日常五字段模板、按预计耗尽小时数提前通知，以及修改配置后历史与查询计划保留修复。

## 功能

- 公开介绍首页、登录注册、监控台和网页安装向导。
- 多账户与宿舍管理；账户拥有独立通知通道，所属宿舍共用。
- 余额、区间估算的每日用量、用电速度、预测曲线、下一次查询时间及事件记录。
- 从请求文本解析查询配置，先预览再确认，不执行粘贴的命令。
- Spug 日常/应急、Webhook、SMTP 可独立启用、保存、清除和主动测试。
- 手机验证码注册、找回和修改绑定手机号；登录使用密码，可接入阿里云 ESA 一点即过验证码。
- 管理员可创建普通账户、修改其密码/手机号和停用普通账户；管理员账户受保护。

## 算法与实现

算法全部随源码提供，不依赖外部预测服务。

| 模块 | 作用 | 状态 |
| --- | --- | --- |
| 精确差分与数据质量 | 微度整数差分、识别缓存、充值歧义、长区间与缺失 | 已实现 |
| 6/24/48 小时专家 | 分别响应短期变化、中期趋势和长期负荷 | 样本足够后参与融合 |
| 加速与减速检测 | 用旧预测误差识别持续变化，避免一次跳变立即改变结论 | 已实现 |
| 分时段专家 | 按昼夜时间暴露拟合负荷 | 达到数据与前向验证条件才启用 |
| 动态融合 | 按已验证的预测误差调整权重 | 优于基础对照后启用，否则使用基础融合 |
| 保守路径与首达时间 | 估算降到预留线、耗尽的时间与夜间风险 | 工程模式，非概率保证 |
| 自适应调度 | 综合风险、模型分歧、变化确认及覆盖截止时间决定下一次查询 | 已实现 |

算法源文件：[`app/engine.php`](app/engine.php)、[`app/model.php`](app/model.php)、[`app/forecast_store.php`](app/forecast_store.php)、[`app/monitor.php`](app/monitor.php)。

详细方法、启用条件、公式对应机制与限制见 [算法实现说明](3.0算法实现说明.md)。状态空间模型、BOCPD 和蒙特卡洛等候选方法未作为已启用功能发布。没有真实历史回测支撑的准确率、漏报率或概率承诺；普通校园接口缺少可信采集时间和完整充值证据时，不输出校准概率。

## 查询与通知规则

- 自动查询默认窗口 08:00～22:00（北京时间），每日最多 8 次，最短间隔默认 60 分钟；基础目标为每天至少 3 次，但预算、失败和窗口约束可能影响实际次数。
- 风险增加或预测不确定性增大时提前安排查询，仍受每日额度和最短间隔限制。每分钟任务也会依据旧预测推进风险检查，但这不等于每分钟访问校园接口。
- 手动查询不计自动额度，不受自动窗口和60分钟间隔限制；仍防止同宿舍并发查询，并受项目启用状态约束。
- 普通通报仅在每周五最后一次自动查询后发送；可单独开启预计耗尽提前提醒（默认12小时阈值），满足条件时立即使用日常通道，不等待周五。
- 默认余额不高于20度进入页面预警；不高于3度或满足可用预测的紧急条件时触发应急通道。20度页面预警不等于即时公众号推送。
- 日常固定模板为标题、等级、对象、时间、内容五字段；修改监控参数不清空历史，真正更换身份的旧版本可单独查看。
- 默认应急通知间隔至少6小时、每天最多2组。具体送达依赖已开启的通道及供应商，接口受理不等于用户已收到。

## 环境

- PHP 8.2+，64位；扩展 `pdo_mysql`、`curl`、`openssl`、`session`、`mbstring`。
- MySQL 8 或 MariaDB 10.11，UTF-8数据库。
- Nginx、HTTPS，推荐 Debian 12 + 宝塔。
- 数据库账户只授予本系统所需库权限；Web运行用户需要写入storage。

## 宝塔安装

1. 下载源码或克隆本仓库，将源码内容放入自己的站点目录；在宝塔选择 PHP 8.2+，**运行目录设为 `/public`**。
2. 创建空数据库，为storage目录配置Web运行用户的读写权限。不要将整个网站设为777。
3. 按 [宝塔部署指南](宝塔安装部署.md) 配置 `/login` 精确路由。文档中的示例域名与路径必须替换成自己的值。
4. 访问 `/dashboard.php`，读取服务器上的 `storage/setup.token` 完成安装，创建自己的管理员。
5. 登录后在抓包解析或项目设置里填写自己的查询信息；源码没有预填身份。
6. 配置需要的通知通道，手动测试可能发送真实公众号、电话、短信或邮件，请使用自己的接收账户。
7. 宝塔添加 Shell 定时任务，每分钟执行以下命令，并替换成实际路径：

```bash
sudo -u www /www/server/php/82/bin/php /www/wwwroot/campus.example.com/bin/cron.php
```

已部署2.2/2.3或3.0的站点请先备份代码、数据库与storage配置，按 [升级说明](升级说明.md) 操作；**不要删除 `storage/config.php` 或重新安装已有数据库**。

## ESA 与短信配置

源码不提供身份标、场景ID、回源密钥或短信调用地址。管理员填入自己的配置前，验证码和短信接入尚未完成。

- AI验证码业务入口为 `/login` 的POST，包括登录、短信、注册、找回及绑定操作；GET用于显示页面。
- `X-Campus-Edge` 的请求头规则应使用 URI路径等于 `/login`，不能用完整URI等于 `/login`，因为请求带有action查询参数。
- 验签通过结果应由ESA返回正式 `T001`，不能手动添加固定通过响应头。
- **当前PHP依赖ESA在业务执行前拒绝无效票据，不提供独立的阿里云服务端验签。必须验证边缘拒绝行为并保护源站后再开放短信功能。** 浏览器成功回调和固定回源头均不能单独证明验证码有效。

完整接入步骤和安全前提见 [部署指南](宝塔安装部署.md) 与 [安全说明](SECURITY.md)。

## 敏感信息保护与打包

首次克隆后启用检查：

```bash
git config core.hooksPath .githooks
```

提交前暂存修改，然后检查或打包：

```bash
python tools/scan-secrets.py
python tools/build-release.py
```

打包仅使用通过扫描的暂存区，输出到忽略的dist目录；未暂存内容不会进入包。不要提交配置、数据库导出、抓包、Token、Cookie、密钥、备份或日志。自动扫描不是完整的安全证明，发布前仍需人工核对。

安全边界和本次审查结果见 [SECURITY.md](SECURITY.md)、[安全审查报告](安全审查报告.md)。生产数据库仍可能保存学校/宿舍/手机号等个人信息，源码脱敏不等于生产数据匿名化。
