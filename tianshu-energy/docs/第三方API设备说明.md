# 第三方 API 平台设备

新增设备选择“第三方 API 平台”，与模拟设备、HTTP 网关共用空间和设备模型。不存在校园独立入口或嵌套旧页面。

## 通用 POST 示例

请求网址：实际平台的 HTTPS 查询地址。请求方式 POST，编码 JSON。

请求头：`{"Authorization":"Bearer 你自己的令牌"}`

请求参数：`{"meterId":"你的电表编号"}`

如果接口返回 `{"code":0,"data":{"balance":42.5,"power":850}}`，剩余电量路径填 `data.balance`，功率路径填 `data.power`，业务成功字段填 `code`，成功值填 `0`。没有提供的字段留空，不能将 W 与 kW、人民币余额与度数混用。数组路径例如 `data.0.power`；不执行任何表达式或脚本。

GET 请求将参数编码为查询参数；POST 可选择 JSON 或 URL 编码表单。请求头可填写 Token/Cookie，自定义 Host、连接长度和传输编码被禁止。HTTPS 校验始终开启，不跟随重定向；本机测试才允许 HTTP。

## 完美校园实例

协议处理选择“完美校园加密协议”，自动填入原有接口 POST 地址，仍可编辑。填写学校编号、查询账户、业务类型（默认0）和房间标识。原加密请求构造、响应解密、外层/内层业务结果检查与房间筛选均复用旧内核。

也可展开“从原请求解析账户信息”，粘贴 JSON、HAR、curl 或表单，仅本机解析。多房间时第一次查询会明确要求选择，返回的房间列表在编辑设备时提供选择，不会随机绑定。保存后手动查询；不需要另行启动校园控制台。

## 数据与调度

API 设备独立保存读数与查询尝试。余额上涨标记可能充值，累计计数下降标记重置；不会扣减已统计的用量。缓存余额不变不等于零消耗，后续下降保留原始平台期锚点。

有效1秒至48小时的余额差额与累计电量差额按时间分摊到小时，与其他设备共用费用和设备排行。该分摊不能定位真实峰值。没有有效区间时不伪造用量。当前功率只汇总10秒内且确有功率字段的读数，其他余额设备显示未知。

耗尽预测复用旧本地保守算法，充值后重新学习，陈旧读数停止作为可靠预测。余额阈值、紧急阈值与预计耗尽预警进入现有告警中心，人工处理为待处理/已确认/处理中/已关闭，监测恢复状态单独记录。v1.0 另有 Webhook/SMTP 通知与本机空间授权，但未迁入 PHP 完整 Tianshu3.0 算法。

默认不开启自动查询；开启后后台持久保存计划，完美校园最短1小时、查询窗口与每日额度限制。手动查询至少间隔60秒。失败退避，自动查询在线程中执行，不阻塞秒级采集。关闭整个平台后停止查询。

已有读数的设备更换请求身份或字段映射时应新建设备，避免把不同电表历史混在一起。请求头凭据可更新。旧设备和历史继续保留。原校园各版本的数据文件不被读取或改写。

## 本机测试边界

自动测试和网页验收均只使用合成数据及127.0.0.1模拟接口。已验证真实HTTP JSON POST、表单POST、字段映射、业务错误拒绝、加密构造/解密筛选、房间歧义、历史、预测、告警、权限和旧能源数据库升级。未使用真实校园账户，也未验证现场电表、费用结算或远程断电。
