# 天枢模拟平台 v1.0.1

独立 Windows 程序，同时提供第三方电表 API、HTTP 设备网关和四照片模拟监控。所有电量、功率、充值及通断均为软件生成，监控是静态照片循环，不连接物理硬件，也不证明真实断电安全。

## 启动

解压完整运行包，双击 `Tianshu.Simulator.exe`。默认打开 `http://127.0.0.1:8792/`，仅监听本机。关闭服务窗口收至托盘；退出服务才会停止模拟。不要单独复制 EXE，运行库和网页必须一起保留。若8792端口被占用，先退出原模拟平台；开发方式可用 `python backend/simulator.py --port 其他端口 --data-dir build/自己的测试目录`。

默认数据目录 `%LOCALAPPDATA%\TianshuSimulator`，与天枢主系统的 `%LOCALAPPDATA%\TianshuEnergy` 完全分开。首次启动生成一个模拟电表和随机 API 令牌，默认没有启用网关。令牌以 Windows 当前账户加密存储；跨 Windows 账户迁移不是免配置恢复。

模拟管理台没有多人账户功能，仅限本人本机调试。不得开放到局域网/互联网，不要用真实账户令牌、生产网关或原有生产设备做映射。程序运行时模拟计量每秒推进；程序关闭、系统挂起期间不补算长时间消耗，不充当结算电表。

## 1. 电表 API

「电表 API」添加或编辑模拟设备，支持仅余额、累计电量、完整计量三种输出。恒定、周期波动和周期超限三种负载可用于验证阈值与趋势；余额可以为负，不会自动断电。表格中的模拟内部状态不等于每种 API 都返回这些字段。

点击设备「接入」查看本机 URL、字段映射与建议名称。主系统中使用名称前缀 `【模拟】`，选择「第三方 API 平台 → 通用 JSON」，GET 或 JSON POST 均可，请求参数 `{}`。在模拟平台查看 API 接入令牌，由用户填入主系统请求头：

```json
{"Authorization":"Bearer 用户在模拟平台查看的令牌"}
```

业务成功路径 `code`，成功值 `0`。完整模式映射：

```json
{"balance_kwh":"data.balance_kwh","cumulative_kwh":"data.cumulative_kwh","power_w":"data.power_w","voltage":"data.voltage"}
```

仅余额模式只填余额映射，累计模式只填累计映射，其余留空。接口会明确携带 `simulation:true`，余额单位 kWh、功率单位 W。这是本地通用 JSON 模拟，不是完美校园加密服务器仿真，不需要校园账号。主系统仍执行自己的查询间隔限制。

「操作」可模拟充值、设置欠费、清零累计读数，以及有开关能力设备的现场通断。修改普通参数不重置历史余额/累计值；清零必须输入确认文字。只读设备不提供现场开关。故障选择支持 HTTP 500、业务失败、格式错误、延迟12秒和冻结读数。延迟可能触发天枢超时；冻结保留该次响应及时间戳，内部负载仍运行。冻结不能用于声称主系统已识别所有厂商缓存/读数停滞策略。

## 2. 设备网关

1. 天枢主系统中建立一个**专用于模拟**的网关，名称建议 `【模拟】测试网关`，保存网关令牌；建立相应 HTTP 网关设备，名称同样加 `【模拟】`，复制设备ID。不能拿已有生产网关或原设备来做演示。
2. 在模拟平台「设备网关」填写天枢当前的本机地址 `http://127.0.0.1:端口` 与专用网关令牌。地址仅允许IPv4回环，不能填外部服务器。令牌留空仅保留当前地址下的既有值，更换地址必须重新填写。
3. 添加映射：左侧选择模拟平台设备，右侧填天枢生成的设备ID。主系统设备必须属于该网关。只读电表对应不具备模拟开关的设备；插座或控制点才开启模拟开关。单相默认220V；若主系统设三相，模拟电压应与主系统线电压配置一致。
4. 确认「专用于模拟的测试网关」，再启用。面板显示遥测接收结果，错误不会冒充连接成功；全部离线时不发送假遥测，但仍可测试指令拒绝。
5. 主系统按原权限、保护规则和目标确认下发操作。模拟平台实际领取指令、记录执行状态并回执，不把“已领取”视为完成。

回执方式：成功（改变模拟状态并报告）、拒绝（不改变状态）、无回执（不执行也不回执，让主系统超时）、回读不一致（验证主系统拒绝不一致状态）。可设置0至25秒执行延迟。指令ID去重；执行状态先落盘，网络错误只重试回执，不反复执行通断；程序重启时未完成指令记为未知，不自动重放。采样序号持久化，重启不会从1开始覆盖主系统的序号历史。

主系统的“网关数据实测”等标签仅说明其通过网关协议接收了数据，并不能验证物理来源；模拟设备必须保留 `【模拟】` 名称，不能用于安全认证或真实节能收益声明。

## 3. 四照片模拟监控

进入「模拟监控」即可预览四张图片循环播放，默认每张停留5秒。页面以 JPEG 实时快照方式每秒获取当前画面，并在新 JPEG 完整加载后替换旧画面，避免刷新闪白。支持立即刷新、暂停/继续、1至60秒间隔设置，以及分别替换四个照片位置。界面仍使用 Art Design Pro / Element Plus 原组件、右侧设置抽屉，没有另写播放器或自绘控件。

在天枢主系统「监控画面 → 新增画面」选择 **JPEG 实时快照**，名称加 `【模拟】`，地址填写：

```text
http://127.0.0.1:8792/mock/camera/snapshot.jpg
```

天枢每秒重新请求一次当前 JPEG，四张照片按设定间隔顺序轮换。浏览器标签进入后台时停止请求，返回页面立即同步；新图加载完成前保留上一帧。该逻辑只负责显示，不进行目标识别、人员检测、行为检测，也不由画面触发告警。

兼容 MJPEG 图片流接口：

```text
http://127.0.0.1:8792/mock/camera/stream.mjpeg
```

MJPEG 通过同一HTTP连接持续传输帧，最多同时4个观看连接。默认推荐 JPEG 实时快照，便于常见监控页面接入。固定照片接口为 `/mock/camera/frames/1.jpg` 至 `4.jpg`。如果更改启动端口，应以模拟平台页面显示的完整地址为准；8793仅用于独立验收预览，EXE默认端口仍为8792。

预置四张图分别为办公区、门店、车间、配电室，使用内置图像生成工具制作并带有“模拟画面”标记。素材与提示词记录在运行包 `web/monitor/README.md`，原图不代表任何实际地点。用户替换时仅支持JPEG，单张不超过3MB、边长16至4096像素、总像素不超过800万。照片与轮播设置存于用户自己的数据目录，不改写发布包内默认素材，不清空其他记录；升级时保留原数据目录即可。

监控图片接口无需登录，任何本机程序都可能读取；不要上传个人隐私照片。全部接口仍只监听本机，不开放外网。上传自己的照片后仍只是静态图片轮播，不能作为现场实时状态的证据。

## 验证边界

原有22项专项自动测试覆盖实际本机HTTP、API认证与三类故障、模拟计量、充值欠费清零、只读能力、网关成功/拒绝/无回执/不一致回执、重复指令、过期保护、重启不重放、只重试回执、序号持久化、会话/同源/CSRF、密钥加密及天枢真实采集适配器接入；新增9项模拟监控测试覆盖四张JPEG资源、轮播顺序、暂停续播、配置持久化、真实MJPEG两帧切换、快照与固定图片、连接上限、上传保护及主系统监控参数接入。测试均为本机合成数据，没有操作真实设备或改写用户原数据库。默认图片生成阶段调用内置图像生成服务，运行程序本身不为监控联网下载图片。最终结果见 `模拟平台验收记录.md`。
