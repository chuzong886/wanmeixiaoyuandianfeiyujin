# 通用能源平台的持续开发约定

- 这是同一个通用系统，适用于企业、工厂、家庭及更多环境；禁止拆成固定的三组模式、三套界面或三套业务内核。
- 空间名称、区域、设备、回路和计价规则可自定义，不硬编码学校、行业或预置真实凭据。
- 在现有设备模型中增加“第三方 API 平台”接口，完美校园是适配实例，不能做成另一个校园入口或嵌套旧系统页面。复用原请求解析、加解密、房间选择与本地预测内核；不得改动原项目或 sources/。
- API 电表统一进入空间设备、大屏、历史、分析与告警。余额不是瞬时功率；无遥测时显示未知。必须区分本地保守预测和 PHP 完整算法，不得宣称算法等同。原校园数据库不能被重置或覆盖。
- 无硬件时，只能明确展示模拟数据。真实控制必须有经过验证的设备协议和执行回执，不能用动画或请求成功冒充实际断电成功。
- 保留保护回路、控制权限、明确目标确认、幂等指令、超时与审计。预算告警不得擅自触发真实断电。
- 电量、功率、电流估算和费用估算必须区分；缺测与零用量必须区分；预测不足样本时不能显示成可靠结果。
- 网页资源随包提供，本地后端默认只监听127.0.0.1。若将来支持局域网、外网或手机访问，应作为明确的新部署能力实现。
- 发布包不能混入 data/、build/、真实数据库、用户凭据或临时测试运行记录。

- 前端使用官方 Art Design Pro 核心菜单、主题组件、Pinia 与中英文语言资源，保留 MIT 许可证与上游版本记录。业务页面和图表跟随日夜主题与主色；不得只改外壳而让表单、弹窗和图表保持固定深色。
- 外观偏好按本机账户持久保存在后端，不能只依赖随机端口下的浏览器本地存储。语言切换不得修改用户输入、设备名称、接口枚举或请求参数。
